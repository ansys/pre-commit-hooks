``pyansys-quality-report`` setup
================================

The ``pyansys-quality-report`` hook evaluates repository quality rules and prints a
scored report with pass, fail, warning, and not-applicable results.

Purpose
-------

Use this hook to enforce repository standards from one command in local development,
CI, and pre-commit.

The report is generated by the
``ansys.pre_commit_hooks.pyansys_quality_report`` CLI and checks all registered rule
families in ``ansys.pre_commit_hooks.quality_rules``.

How to use in pre-commit
------------------------

Add the hook to ``.pre-commit-config.yaml``:

.. code:: yaml

   - repo: https://github.com/ansys/pre-commit-hooks
     rev: v0.8.0
     hooks:
     - id: pyansys-quality-report
       args:
       - --repo-root=.

The legacy ``tech-review`` hook is maintained as a compatibility alias and points to
the same quality report entry point.

Rule groups and purpose
-----------------------

Rules are organized by family so results are easier to filter and triage:

.. list-table::
   :header-rows: 1
   :widths: 25 15 60

   * - Family
     - ID prefix
     - Purpose
   * - Project Metadata
     - ``PM``
     - Project identity, ownership, policy files, README and packaging metadata.
   * - CI/CD
     - ``CI``
     - Workflow quality and required automation actions.
   * - Dependabot
     - ``DB``
     - Dependency update and grouping configuration quality.
   * - Pre-commit
     - ``PC``
     - Repository pre-commit configuration quality.
   * - Documentation
     - ``DOC``
     - Documentation structure and required Sphinx/docs settings.
   * - README
     - ``RM``
     - README structure and required sections.
   * - Build System
     - ``BS``
     - Build backend and packaging-system consistency checks.
   * - Security
     - ``SEC``
     - Security hardening checks, including workflow pinning.
   * - Labeler
     - ``LB``
     - Labeler file and behavior checks.
   * - Vale
     - ``VL``
     - Vale configuration and vocabulary checks.
   * - MCP Release Readiness
     - ``MCP``
     - MCP-specific release-readiness checks.

Rule IDs
--------

Each rule has an ID such as ``PM014`` or ``CI010``. Use IDs to select or ignore
specific checks.

To list all available rule IDs and metadata:

.. code:: bash

   pyansys-quality-report --metadata

How to use from CLI
-------------------

Run against the current repository:

.. code:: bash

   pyansys-quality-report --repo-root .

Show only failing and warning checks:

.. code:: bash

   pyansys-quality-report --repo-root . --fails-only

Run selected checks:

.. code:: bash

   pyansys-quality-report --repo-root . --check PM014,PM017

Run a selected family:

.. code:: bash

   pyansys-quality-report --repo-root . --family security

Export JSON for CI post-processing:

.. code:: bash

   pyansys-quality-report --repo-root . --json

Ignore selected checks for a run:

.. code:: bash

   pyansys-quality-report --repo-root . --ignore PM022,PM024

CLI arguments
-------------

.. list-table::
   :header-rows: 1
   :widths: 20 20 60

   * - Argument
     - Default
     - Description
   * - ``--repo-root``
     - ``.``
     - Repository root to scan.
   * - ``--json``
     - ``False``
     - Emit a JSON report.
   * - ``--metadata``
     - ``False``
     - Print check metadata (IDs, families, labels).
   * - ``--check``
     - Empty
     - Run only selected check IDs. Accepts repeated and comma-separated values.
   * - ``--family``
     - Empty
     - Run only selected families. Accepts repeated and comma-separated values.
   * - ``--fails-only``
     - ``False``
     - Show only fail and warning entries in text output.
   * - ``--all``
     - ``True``
     - Keep passing checks visible in text output (default behavior).
   * - ``--ignore``
     - Empty
     - Ignore selected check IDs. Accepts repeated and comma-separated values.
   * - ``--fix-missing``
     - ``False``
     - Run legacy bootstrap to create missing baseline files/directories before checks.
   * - ``--license``
     - ``Apache-2.0``
     - License used by legacy bootstrap checks. Only Apache-2.0 is supported.

Legacy note
^^^^^^^^^^^

Most repositories should not need legacy bootstrap arguments.
If you are running with ``--fix-missing``, use only ``--license`` for normal
workflows.

Additional features
-------------------

- Rule selection by ID or family for targeted validation.
- Ignore list from CLI or from ``pyproject.toml``.
- JSON output for CI pipelines and machine parsing.
- Colored text output for quick local triage.
- Auto-discovery of checks from rule-family modules.
- Compatibility alias via ``tech-review`` hook.

Ignoring checks in ``pyproject.toml``
-------------------------------------

You can define ignored checks in ``pyproject.toml``:

.. code:: toml

   [tool.ansys-pre-commit-hooks]
   ignore = ["PM022", "PM024"]
